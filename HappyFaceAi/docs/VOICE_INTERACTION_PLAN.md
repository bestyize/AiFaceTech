# 语音互动方案与实现范围

## 目标

倾听期间即可回应，视觉与语音共用行为控制器。开始收音显示倾听；音量产生轻微的面部活动；支持中间转写的识别器可在用户说完前触发短暂的关心、开心、打招呼等反应。中间转写修改或消失时撤销对应反应，不把未经确认的内容加入对话记录，也不提前调用大模型。

## 输入与分层

1. 交互阶段：倾听、识别/思考、播放、待机，用于稳定的基本状态。
2. 实测音量：PCM16 RMS 或系统识别器的音量回调，归一化到 0–1；只影响倾听活动，不判断情绪。活动停止后快速衰减。
3. 中间转写：Android 系统识别、iOS 系统识别及实时供应商提供的非最终文字；仅在当前倾听阶段使用，显示时间有限，并随转写修订重新计算。
4. 最终转写：沿用现有提交和生成回复链路，决定确认后的内容反应。

语音模块输出统一的 VoiceObservation，宿主在主线程转为 BehaviorEvent。行为模块不认识麦克风、具体服务商或识别 SDK。禁止在音频采集线程直接操作行为控制器。

## 第一版语义规则

问候 → 打招呼；夸奖 → 害羞笑；表达难过 → 安慰；分享开心或好消息 → 开心；感谢 → 感谢；道歉 → 安心；晚安 → 晚安。词组规则排除明确的否定词组，例如“不难过”“不可爱”；复杂讽刺、歧义、跨句语义暂不由关键词判断。

倾听中的语义反应属于当前话语，不被此前视觉/抚摸临时反应替代。识别/思考阶段仍显示思考，播放仍使用现有说话表情；最终文字决定的内容反应在回答完成后显示。关闭对话、取消录音或开始新话轮时清理倾听反应和音量。

## 支持边界

分段 SenseVoice/MiMo 当前在录音结束后识别，因此可以实时显示音量活动，但无法在录音中按内容反应。系统 ASR 和实时服务是否返回中间文字取决于设备服务和供应商；没有中间文字时保持倾听，不伪造识别。语气情绪分类、模型结构化表情建议及按实际播放进度同步的口型不属于本版。

## 验证

离线验证视觉映射/连续确认、音量归一化、语义否定、中间文字修订、阶段优先级和停止清理。Android 验证系统 ASR 的回调、分段录音音量与实时 PCM；在线识别需要已配置供应商和有效凭据。iOS 源码保留同一事件契约，需 macOS/Xcode 完成构建与硬件验收。
