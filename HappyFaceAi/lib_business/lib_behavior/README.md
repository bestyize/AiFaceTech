# lib_behavior：行为与表情决策

跨平台规则核心，消费 `BehaviorEvent`，输出 `BehaviorState`。只依赖表情模块；不采集音视频、不请求模型，也不持有 Compose 状态。宿主使用同一单调时钟调用 `accept(event, nowMillis)` 和 `state(nowMillis)`，并在同一线程串行调用。输出包含表情、交互阶段、触发原因和临时反应结束时间。

## 第一版规则

| 输入 | 输出 | 持续时间 / 冷却 |
| --- | --- | --- |
| 倾听 / 处理中 / 播放 | LISTENING / THINKING / SPEAKING | 随语音流程切换 |
| 抚摸按钮 | HAPPY | 2.4 秒 / 0.5 秒 |
| “真可爱”“你很棒”“喜欢你”等 | BASHFUL_SMILE | 8 秒 / 1 秒 |
| “难过”“伤心”“不开心”等 | COMFORTING | 8 秒 / 1 秒 |
| “你好”等 | GREETING | 5 秒 / 3 秒 |
| 人进入画面 | GREETING | 2.4 秒 / 15 秒 |
| 静态点赞手势 | APPROVING | 2.4 秒 / 5 秒 |

语音阶段优先于临时反应；临时反应依次为抚摸、话语、视觉。临时反应到期后恢复用户选择的基础表情。话语反应可在语音结束后显示，但绝不过期补播。视觉只在待机时触发，不打断当前对话，不排队补播。离开陪伴页或关闭对话会清理当前交互。

视觉输入至少连续三个不同时间标记的有效帧才确认。超过一秒的旧结果、重复或乱序结果、未来时间标记被忽略；超过一秒的感知间隔清理连续证据。人消失两秒后可重新迎接（仍受冷却限制）；持续点赞不会重复触发，必须先松开再确认。

## 应用接入

`shared/App.kt` 持有控制器，用 50ms 时钟更新到期状态。`VoiceConversationOverlay` 转发阶段和已提交的用户文字（包括最终实时语音转写）；`LivingPerception` 在陪伴页订阅相机和感知结果，在工作线程推理、主线程提交事件。关闭页面或应用进入后台会停止感知并释放相机。

视觉沿用已有设置，至少一项已开启且模型可用时才启动相机；不会自动开启任务或下载模型。人脸或 person 检测置信度至少 0.7，点赞手部置信度至少 0.7，并保留原感知任务的阈值过滤。模型缺失时请先到视觉设置下载。相机权限被拒绝或运行失败时显示提示，语音与手动表情仍可使用。

文字规则只是关键词匹配，暂不理解否定、讽刺或复杂上下文；不把视觉表情分类当成用户真实情绪。第一版也不包含声音语气识别、长期人格、模型表情建议或音频口型。语音播放期间仍展示统一 SPEAKING，口型与情绪叠加属于后续工作。

## 验证

```text
gradlew.bat :lib_business:lib_behavior:jvmTest :lib_business:lib_vision:jvmTest :shared:jvmTest :androidApp:assembleDebug
```

规则测试覆盖阶段优先级、反应到期、基础表情恢复、视觉连续确认、重复与过期结果、冷却与重入、对话期间的视觉抑制及交互清理。相机、麦克风和目标设备的推理耗时需要实机验收；iOS 需要 macOS / Xcode 构建验证。
