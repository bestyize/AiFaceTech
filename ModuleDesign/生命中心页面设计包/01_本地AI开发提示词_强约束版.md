# 本地 AI 开发提示词（强约束版）

你正在继续开发一个 **AI 小生命 App**。当前首页是沉浸式全屏表情界面，不是传统聊天 App。

请先阅读：
1. `生命中心页面设计说明.md`
2. `02_Compose页面结构与组件说明.md`
3. `03_信息架构与交互流程.md`
4. `04_完整页面清单与路由.md`
5. `assets/生命中心_横屏设计稿.png`

然后在**现有工程中**实现「生命中心」。

## 产品背景
产品不是“AI 工具”，而是一个有表情、人格、记忆、声音、能力与成长状态的 **AI 小生命**。

未来会逐步加入：
- 外部大模型
- 声音 / TTS
- 人格
- 长期记忆
- 表情系统
- Skill / 能力
- 生活节律
- 账号与设备
- 桌面 AI 盒子
- 机器人

因此需要一个统一二级入口：**生命中心 / Companion Center**。

## 必须遵守
1. 不要把首页改成传统功能首页。
2. 不要增加底部 TAB。
3. 首页仍然是沉浸式生命体。
4. 生命中心不是传统 Settings，而是“这只生命由哪些部分组成”。
5. 横屏优先，但代码必须支持窄屏自适应。
6. 必须提交真实可运行实现，不要只给类定义、TODO 或静态 Mock。
7. “表情与外观”必须能真正导航到现有表情设置页。
8. 其它尚未完成的详情页可以先做统一 Placeholder，但按钮必须真实可点。

## 本期目标
完成：
```text
沉浸式首页
   ↓ 长按 / HUD
生命中心
   ├─ AI 大脑
   ├─ 声音
   ├─ 人格
   ├─ 记忆
   ├─ 表情与外观
   ├─ 能力
   ├─ 生活节律
   └─ 设备与系统
```

## 页面布局
参考 `assets/生命中心_横屏设计稿.png`

左侧：
- 角色形象
- 名称
- 陪伴天数
- 在线状态
- 人格摘要
- 陪伴文案
- 进入陪伴
- 更多设置

右侧：
- 2 列能力卡片
- 最近变化 / 成长时间线

## 数据驱动
不要把整页内容直接写死在 Composable 里。至少建立：
```kotlin
data class CompanionProfile(...)
data class LifeCenterFeature(...)
data class RecentChange(...)
```

## 路由
至少定义：
```text
living
lifeCenter
brain
voice
personality
memory
appearance
skills
rhythm
deviceSystem
```

## 视觉
- 深色背景
- 暖金为主强调色
- 粉 / 紫 / 蓝少量作为分类色
- 大圆角
- 低噪音
- 柔和玻璃感
- 不要赛博朋克
- 不要像后台 SaaS

## 首页交互
推荐：
- 轻点：出现 2～4 秒轻量 HUD（对话 / 抚摸 / 生命中心）
- 长按：直接进入生命中心
- 返回全屏：回沉浸式角色页

## 自适应
优先使用宽度判断，而不是仅用 orientation：
```kotlin
BoxWithConstraints {
    val wide = maxWidth >= 840.dp
}
```

## 禁止事项
- 删除现有首页
- 重建无关新工程
- 复制第二套表情系统
- 把所有代码塞进一个 Composable
- 引入不必要大型依赖
- 只返回代码片段却不修改项目
- 把“预留接口”说成“已实现”

## 完成后必须
1. Gradle Sync
2. Build
3. 修复编译错误
4. 实际运行
5. 验证 首页 → 生命中心 → 表情与外观 → 返回
6. 验证横屏
7. 尽可能验证窄屏

## 最终汇报
只汇报真实完成项，并明确列出尚未实现的真实能力，例如：
- 大模型 API
- TTS
- 长期记忆
- Skill 后端
